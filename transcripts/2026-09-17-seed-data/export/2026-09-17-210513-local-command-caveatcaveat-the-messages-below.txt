  Who gets seeded
  - Owner A is the real test user. Their sub comes from SEED_OWNER_A_SUB, and no

  What the seed contains
  - Collections: each Owner gets two, including one both Owners share with
    different casing (Reading / reading), and one of them has no Bookmarks.
  - Bookmarks: each Owner also gets some Uncategorised Bookmarks, and both
    Owners have some of the same URLs.
  - Owner B's text: every title and note says outright that it belongs to B and
    should never be visible to A.
  - A's larger Collection: about 55 Bookmarks in one Collection, so "Load more"
    shows up on /bookmarks and on that Collection's page.
  - Order: each row has its own createdAt, a minute apart, so the order is the
    same on every run.

  When it runs
  - Code shape: prisma/seed.ts exports seed(prisma, { ownerA, ownerB }), and a
    small CLI entry point in the same file reads the environment and calls it.
  - On npm run dev: it becomes migrate && db:seed && concurrently …. The seed
    only runs for an Owner with no Collections and no Bookmarks. That means
    restarting keeps the reviewer's work, and deleting everything brings the
    seed back.
  - If SEED_OWNER_A_SUB isn't set: only B is seeded, and a clear message
    explains how to set the variable. A is seeded on the next dev after that.
  - npm run db:seed:reset: deletes and re-creates B's rows, and A's if the
    variable is set, in one transaction. It refuses to run unless DATABASE_URL
    points at the local database on localhost:5434.
  - How it's run: prisma db seed through migrations.seed in prisma.config.ts,
    using Node 24's built-in TypeScript support. If that doesn't work with the
    generated Prisma client, it falls back to a pinned tsx.

  What the reviewer does
  - Find their sub: copy the Bearer token from the Network tab, then run npm run
    whoami --prefix backend -- <token>. It decodes the token locally and prints
    only sub. The README won't suggest jwt.io.
  - Check that B's rows exist: run a psql command through docker compose exec,
    documented in the README (slice 7).

  6. None of B's rows appear in any of A's lists, including a q search for a
