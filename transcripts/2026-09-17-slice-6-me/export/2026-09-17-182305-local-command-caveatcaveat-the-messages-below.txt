  Why run 35213483028 (c8bc67d) failed

  Both c8bc67d and 88d13c5 only add transcript .txt files, so neither commit
  could change what the tests do. One frontend test failed:

  FAIL src/routes.spec.tsx > the app shell > loads /me once, not after each save
  or navigation
  TestingLibraryElementError: Unable to find an accessible element with the role
  "tab" and name "Collections"

  The test is at frontend/src/routes.spec.tsx:129:

  await user.click(within(dialog).getByRole('button', { name: 'Save' }));
  await waitFor(() =>
  expect(router.state.location.pathname).toBe('/bookmarks'));
  await user.click(screen.getByRole('tab', { name: 'Collections' }));   // ← 
  fails here

  The cause: once Save succeeds, the router moves to /bookmarks straight away,
  but the MUI edit dialog is still playing its closing animation. While the
  dialog is open, MUI puts aria-hidden="true" on the rest of the page, and the
  failure's DOM dump shows exactly that:

  <body style="padding-right: 1024px; overflow: hidden;">
    <div aria-hidden="true">
      <header ...>

  The only accessible elements it lists are the dialog's own controls (Delete,
  Close, and Save, which still has Mui-focusVisible). The tabs are there but
  hidden from the accessibility tree. getByRole checks only once and doesn't
  retry, so if the animation hasn't finished by then, the test fails.

  Why 88d13c5 passed

  It won the race: on that run the dialog finished closing before getByRole ran.
  It's the same race either way. The earlier run 35213316247 (2719d1c) failed
  on the same line with the same error. So the test has failed twice and passed
  once on this branch, and a rerun would probably pass or fail at random.

  The similar test "saves with PUT, closes, and keeps the filters" (line 365)
  doesn't have this problem because it never touches the page behind the dialog
  after closing it.

  Fix

  Make the test wait for the dialog to be gone before clicking the tab:

  await waitFor(() =>
  expect(router.state.location.pathname).toBe('/bookmarks'));
  await waitForElementToBeRemoved(() => screen.queryByRole('dialog'));
  await user.click(screen.getByRole('tab', { name: 'Collections' }));

  A smaller alternative is await user.click(await screen.findByRole('tab', { 
  name: 'Collections' })), which keeps retrying until the tab is visible.
  Waiting for the dialog to close says more clearly what the test depends on.

  I haven't changed anything. Want me to apply the fix and run the test in a
  loop to check it's stable?
