⏺ The easiest place is the Network tab in your browser's dev tools. The SPA
  keeps the token in memory only (Auth0's default), so it isn't in localStorage.

  1. Start the app and sign in as the test user.
  2. Open dev tools (⌥⌘I), go to the Network tab, and filter by Fetch/XHR.
  3. Open a page that calls the API, such as the bookmarks list. Reload if the
     list shows no requests.
  4. Click a request to your API. Under Headers → Request Headers, find
     Authorization: Bearer eyJ….
  5. Copy only the part after Bearer . That's the token.

  Don't use the /oauth/token response. You'll also see a request to
  …auth0.com/oauth/token. Its response holds both an access_token and an
  id_token. If you take it from there, use access_token, not id_token. The API
  request header always holds the right one.

  The token should work for /userinfo. It carries two audiences: your API and
  Auth0's /userinfo. That's because the SPA asks for openid profile email along
  with your API audience (frontend/src/App.tsx:24-25). This is exactly what #16
  is checking.

  The token expires after the lifetime set on your API in Auth0 (often 24
  hours), so run the probe soon after copying it. To keep the token out of this
  session's log, run the probe in a separate terminal rather than with ! here,
  then paste back only the output.
